# Simple Sub2API 功能亮点与设计哲学 (Features & Design Philosophy)

`Simple Sub2API` 是一款专为**独立开发者、极客个人及小团队协同**设计的轻量级、高保真 API 代理与订阅账户调度网关。不同于市面上普遍存在的多级中转与商业计费系统，本项目坚持**“去商业化、绝对透明、极致高可用”**的独立单租户（Single-Tenant）设计哲学。

---

## 🌟 核心功能亮点

### 1. ⚡ 零商业负担，极简自调整额度均衡
* **亮点描述**：完全移除了商业收费中转系统里繁琐复杂的“多级计费”、“代币划转”、“划扣统计”与三方数据库依赖。网关配置纯粹友好，所有账号、路由和连接状态实时可视。
* **业务场景**：完美满足个人多账号及小团队协作场景下“有人不够用，有人用不满”的资源错配痛点。在本地/团队内部实现精细化自调整路由，最大化释放闲置账号额度的潜能。

### 2. 🛡️ 高保真透明代理，杜绝掺水与降智混淆
* **亮点描述**：坚守高保真代理的底线。网关对上游接口返回的数据**不做任何篡改、上下文削减或混淆**，也绝不在后台注入多余的系统提示词或转换模型名称。
* **业务场景**：开发人员在进行复杂的 IDE 辅助编程（如 Claude / Copilot 编码）、长文本推理或高精密研究时，能够接收到 100% 官方原汁原味的推理结果，保障开发逻辑的精确，彻底告别商业转售中转常见的“返回内容变笨”和“降智”现象。

### 3. 🔒 独立安全域，严防交叉滥用风控
* **亮点描述**：网关采用严格的“单租户单主控（Single-Tenant）”结构，不提供面向公众的大规模跨客户端 API Key 分发服务。所有的请求鉴权均在本地私有网关验证。
* **业务场景**：这从源头上杜绝了因商业化“万人共用出口”导致的高频 IP 风控滥用问题。保护您珍贵的订阅账号不被服务商打上“异常流量”或“高风险代理”标签，全面保障个人与协作团队的持久可用性与数据隐私。

### 4. 🔄 智能路由组管理与平滑轮换调度
* **亮点描述**：支持对订阅账号执行多维度标签化 Group 分组管理。支持**最少连接（Least Connections）、P2C 算法、轮询（Round-Robin）和手动权重（Priority）**四种智能调度方案。
* **业务场景**：内置并发连接感知与实时配额限制检测（Weekly Quota Protection）。当某个账号突发性发生源头改密失效、过期或被源头锁定时，网关瞬间拦截并启动**秒级无感 Failover 自动降级切换**，由组内其他健康账号无感重试，保障客户端连接高可用。

### 5. 🌐 零开孔公网安全通道 (Cloudflare Tunnel)
* **亮点描述**：内置原生的 Cloudflare Tunnel（Cloudflared）进程保活与自动治理引擎。支持免域名的一键快速匿名隧道（Quick Tunnel）和自建顶级域名的命名隧道（Named Tunnel）。
* **业务场景**：在 NAT、多层内网或家用 NAS 等完全没有公网 IP、无法配置路由器端口映射（Port Forwarding）的环境下，隧道仅向外建立加密长连接出站。完全杜绝入站开放 TCP 端口的安全风险，在 Proxies 页面中内嵌终端级实时 Stderr 日志与呼吸状态灯，提供极致的远程访问与异地协同体验。

## 🧭 设计哲学对比矩阵 (Comparison Matrix)

| 核心维度 | 传统商业中转网关 (Commercialized) | Simple Sub2API 极客网关 (Single-Tenant) |
| :--- | :--- | :--- |
| **设计定位** | 追求转售利润、多级代理加盟、复杂计费扣费 | **追求极简、自用/团队额度平滑均衡、小团队协同** |
| **数据保真度** | 掺水削减上下文限制、恶意提示词注入以压低成本 | **100% 原生官方接口高保真透明代理，无任何篡改** |
| **账号安全性** | 万人共用出口 IP 和 API Key，极易被标记滥用封号 | **本地私有网关绝对隔离，专卡专用，防源头风控** |
| **网络暴露方式** | 直接向公网开放服务器 TCP 端口，面临扫描攻击风险 | **基于 Cloudflare Tunnel 零入站开孔安全穿透** |
| **操作复杂度** | 臃肿的用户组、账单划转设置，庞大的数据库依赖 | **轻量化 Go 内存状态机，单 JSON 配置热更新** |

---

> [!NOTE]
> **设计遵循合规规约**：
> 本网关严格对齐个人订阅账号池的高可用调度，不涉及任何商业售卖、账单拆分或多租户商业运营。所有穿透流量完全依赖用户自己设备上的开源 `cloudflared` 二进制与 Cloudflare 官方零信任节点，符合纯自用高可用规约。
